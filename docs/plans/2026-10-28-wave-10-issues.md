## Design rule

`CONTRIBUTING.md` states it, and this plan does not restate it. The lane's controls, each with its
sentence:
- **#34's moved guards.** The base-mismatch refusal: the adversary is a pull request whose caller
  file names another `base:`. The anchor is `github.base_ref`, the platform's report of the pull
  request's base, which the pull request cannot write. The qualified ref: the adversary is a tag
  called `origin/<base>`. The anchor is `refs/remotes/origin/<base>`, which `actions/checkout`
  writes from the remote's branches. The `..` containment: the adversary is a caller file whose
  `path:` points the gates at another checkout's configuration (`../stayfixed`, the workflow's
  own). The anchor is the checkout the runner made, and the check bounds the value lexically, so
  writing the value does not move it.
- **#34's deleted guards.** The `path:` character grammar and its newline refusal guarded the
  lines the step appended to `$GITHUB_OUTPUT`. After #34 nothing reaches it, and `--annotate`
  writes a path into a workflow command only when it matches `PATH_VALUE`
  (`src/stayfixed/assess/report.py`), so they stop no adversary. The grammar also refuses a
  legitimate root with a space or a non-ASCII name. Both go, with their bash case, and no refusal
  echoes the value (Task 6). `check-ref-format` stays as a plain call with no mutation entry: it
  refuses no legitimate branch, and the qualified ref already decides which commit is read.
- **#37's cgroup end, if it ships.** The adversary is the gate's own descendant, which the
  repository's command starts, so the repository could equally leave a process behind by other
  means. The cgroup end is therefore a **convenience**: it ends a leftover where the kernel
  delegates a cgroup to the user, never refuses, and never warns when there is none. `docs/cli.md`
  says it is Linux-only and best-effort.
- **#47** changes a remedy and a name, not a verdict.

A wave that finds it must add a control stops and puts it to the owner with its sentence written
(umbrella, "Design rule").

## Lifecycle matrix (IS1, walked at pre-flight and by the correctness seat)

The keys IS1 changes are `stayfixed.state`, which is removed, and `stayfixed.enforced`, whose
meaning loses the `installed` rule. Both are `GATE_PARAMETER`. The pre-flight reads
`src/stayfixed/config/classes.py` for the layers that class admits, and walks only those.

| Change | Expected |
|---|---|
| `state` set in the project's file | the loader refuses `[stayfixed] has unknown key(s): state`; every command that loads refuses, and none writes |
| `state` set in a layer the class does not admit | as today for any key outside its class: the pre-flight quotes the class table's refusal |
| `state` in the base's copy only (an upgrade pull request) | `stayfixed gate` fails with `BASE_DOES_NOT_LOAD` (exit 1), whose remedy is a direct push |
| `enforced` grows (a superset of the base's) | `tightened` |
| `enforced` reordered, or unchanged | no change |
| `enforced` loses a gate the base lists | `refused` |
| `enforced` removed from the file, the base listing gates | `refused` (an empty list is not a superset) |
| `enforced` removed, the base listing none | no change |
| `enforced` names an unknown gate, or one twice | `GATES_UNKNOWN`, `GATES_TWICE`, as today |
| `adopt promote` whose write refuses part-way | nothing written; the remedy names `enforced` and the one-line value it was writing |
| `adopt promote` with every gate already listed | `ALL_ENFORCE`, with no write |
| `init` over a file that spells `state` | the merged document fails the load check (exit 1, the loader's sentence) and nothing is written |
| `uninstall` | takes `stayfixed.toml` back, its owned-key record re-stamped by the last `promote`, as today |

## Review focus

Each line is a failure no single task's tests would show, with the test that pins it.

1. **A move that changes behaviour.** Task 1 and Task 2 are pure moves. The existing tests of
   `read_base`, `judge` and `stayfixed gate` run unchanged except for their imports. A changed
   assertion in `tests/assess/test_gate_command.py` or `tests/assess/test_read_base.py` during
   wave A is a finding.
2. **A missing roadmap now reads as "could not run", not as a finding.** For an enforced `trail` gate
   both fail the run, and for an advisory one both exit 0. Task 3 pins the gate result, and `docs
   trail --check` keeps its own message and exit, pinned by its existing test.
3. **`installed` silently kept by a default.** Task 4 pins that a file with no `enforced` enforces
   nothing, whatever gates it configures.
4. **The two gate steps resolving different bases.** Both resolve
   `refs/remotes/origin/<base>` in one checkout that nothing fetches into between them. Task 7
   pins that neither step reads a base from the other, and the pull request says why the two
   resolutions agree.
5. **`head_ref` reaching Python.** Task 7 pins that `check.yml` names no `head_ref` anywhere.
6. **A guard lost in the move.** Task 6's cases are the successors of the bash cases for the moved
   guards, and its `check-ref-format` case holds the plain call. Task 7 deletes the bash cases only
   after `git log` shows Task 6's commit. The `path:` grammar's case is deleted, not moved (Design
   rule).

### Task 12: Measure whether a cgroup ends a descendant that left the group (controller-run)

The probe is a script the controller writes into the scratch repository, never into this one. In
Python's standard library, it:
1. reads `/proc/self/cgroup` (`0::<path>`) and prints the path, and whether
   `/sys/fs/cgroup<path>` is writable and holds `cgroup.kill`;
2. creates a child cgroup `probe-<pid>`, starting a `sh -c` command with
   `subprocess.Popen(..., start_new_session=True, preexec_fn=<write "0" to the child's
   cgroup.procs>)`; the command starts `setsid sleep 300 &` and prints that pid;
3. ends the command's process group as `stayfixed.processes.kill_group` does, then checks that the
   `setsid` pid is alive (the issue's shape);
4. writes `1` to the child's `cgroup.kill`, waits up to 5 seconds for `cgroup.events` to read
   `populated 0`, checks that the pid is gone, and removes the child.

It prints every step's result and exits 0 whatever it found.
