On Python 3.11 to 3.13, a committed link into a directory its user cannot search, or to a name
longer than the filesystem allows, no longer ends a command in an internal error that printed the
path on this machine: the command refuses (exit `2`) naming the link, on every Python. A
`.stayfixed` of either kind did this to `stayfixed init`, `upgrade` and `uninstall`; on Python
3.14 the last two said instead that the footprint's manifest was not there. A `.codex` of the
first kind did it to `stayfixed attach`, and `attach --check`, which reported nothing wrong,
refuses it too.
